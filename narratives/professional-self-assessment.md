# Professional Self-Assessment

Completing my computer science coursework and developing this ePortfolio gave me a chance to look at my work as one body of experience instead of as separate assignments. Earlier in the program, I focused heavily on getting programs to work. As I moved through more advanced courses, I became more concerned with how software is structured, how it can be tested, how data is managed, how security should be considered, and how other developers or stakeholders will understand the decisions behind the code.

My main career goal is gameplay programming, although the program also made me more open to software engineering roles. Game development has remained important to me because I enjoy building systems that combine technical problem-solving with interactive experiences. Projects in Python, Java, C++, Unreal Engine, full-stack development, graphics, testing, and databases gave me a wider view of the field and helped me understand that strong fundamentals matter across specialties.

Team-based work was one of the areas that helped me grow outside of individual programming. In digital game development, I worked as a project manager/producer and developer on a team project. That required organizing work, communicating through shared tools, tracking features and testing, and making decisions when scope or implementation changed. The experience showed me that a working technical solution is only one part of a successful project. A team also needs clear communication, shared expectations, and a way to make decisions when priorities compete.

Communication became more important as the program progressed. I have written design documents, project reflections, testing plans, technical narratives, and this capstone code review. The code review required me to explain existing functionality, identify weaknesses, and justify planned enhancements in a way another developer could follow. The artifact narratives required a different kind of communication because they connect technical details to the reason each change matters. Together, those experiences strengthened my ability to adjust technical explanations to the audience and purpose.

Data structures and algorithms became more meaningful when I could connect them to a feature instead of treating them only as theory. In the Zelda-inspired text game, the room map naturally forms a graph. For the algorithms enhancement, I used breadth-first search to create a hint system that finds a shortest path toward a missing item or the final encounter. A queue, visited set, predecessor mapping, and deterministic direction order support the search. That enhancement helped me evaluate why BFS fits an unweighted graph and how an algorithm can improve gameplay without taking control away from the player.

My database work is represented by Travlr Getaways, a full-stack application using Express, Angular, MongoDB, Mongoose, and a REST API. The capstone enhancement strengthened schema validation, data types, indexes, filtering, CRUD behavior, authentication error handling, and testing. That work made the relationship between the database, API, and user interface much clearer. It also reinforced that decisions at the data layer can affect every other part of an application.

Security became part of my development process rather than something I considered only at the end. Across the capstone, I used safer input handling, validation, controlled error responses, JWT-protected operations, restricted CORS origins, and query allowlists. I also saw how small implementation details can expose unnecessary information, such as raw database errors returned to a user. Correcting those problems helped me build a stronger security mindset around validation, access control, error handling, and protecting application internals.

The artifacts in this portfolio fit together as a progression. The software design enhancement shows how I can take an early project and reorganize it into a more maintainable structure. The algorithms enhancement builds on that improved structure with graph traversal, a practical search feature, data-structure choices, validation, and automated testing. The database enhancement demonstrates full-stack development and secure data management across several application layers. The code review connects the starting point to the final work and explains why the enhancements were selected.

As I complete my degree, I see this portfolio as evidence that I can do more than write code that produces the expected output. I can review an existing system, identify weaknesses, choose practical improvements, test the results, explain trade-offs, and communicate why those decisions matter. Those are skills I plan to continue developing as I move toward gameplay programming and software engineering roles.
